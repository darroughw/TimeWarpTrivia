# Apple TV app — notes for Claude

Native SwiftUI tvOS app (deployment target **tvOS 16**). Each view in
`TimeWarpTrivia/Views/` is a port of the matching web TV screen in
`../components/tv/`, driven by `GameFlowViewModel` (port of
`../app/_game/LiveTvFlow.tsx`). Keep gameplay behavior in parity with the
web; visuals may go further than the web where TV benefits. See
`README.md` in this folder for the why behind the architecture.

## Building and running

- `TimeWarpTrivia.xcodeproj` is **generated by xcodegen** from
  `project.yml`. After adding, removing, or renaming any `.swift` file (or
  changing `project.yml`), run `xcodegen generate` in this folder. Never
  hand-edit `project.pbxproj`.
- Open `TimeWarpTrivia.xcodeproj` (not the folder) and use the
  **TimeWarpTrivia** scheme with an Apple TV simulator. The simulator
  needs no signing team.
- From a shell, `xcode-select` may point at Command Line Tools — prefix
  with `DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer`:
  ```
  xcodebuild -scheme TimeWarpTrivia -destination 'platform=tvOS Simulator,name=Apple TV 4K (3rd generation) (at 1080p)' CODE_SIGNING_ALLOWED=NO build
  ```

## Demo mode (view any screen without a real game)

DEBUG builds accept launch arguments that fill the app with sample
players/questions, so any screen can be checked without phones and
**without creating a room in the production Supabase project** (the app
talks to prod; there is no dev backend):

```
-demoScreen lobby|deepcuts|countdown|question|transition|scoreboard|block|end
-demoDecade all|60s|70s|80s|90s|2000s|2010s
-demoDeepCuts YES   # any screen, in Deep Cuts mode (purple theme)
```

Set them in Edit Scheme → Run → Arguments, or
`xcrun simctl launch booted com.timewarptrivia.appletv -demoScreen end -demoDecade 80s`.
Implemented in `GameFlowViewModel.loadDemo` (bottom of that file). Buttons
on demo screens don't work — nothing in demo mode talks to the network.
**Don't commit demo arguments in the shared scheme file**
(`xcshareddata/xcschemes/TimeWarpTrivia.xcscheme`) — every Run would open
the demo screen for everyone.

## Deep Cuts mode

The lobby switches between decade mode (`LobbyView`) and Deep Cuts mode
(`DeepCutsLobbyView`) in place — `RootView` shows the Deep Cuts lobby
whenever `room.deepCutTopicId` is set. (The web instead uses a separate
`/deepcuts` route per TV session.) Picking a topic also resets
`decade_filter` to `all`; the footer's "Decades" button nulls the topic.
`DeepCutsLobbyView` mirrors `LobbyView`'s layout (players left, picker
sidebar right, same footer) with the `DeepCutsLogo` asset
(`public/logo-deepcuts.svg`) — keep the two lobbies in step. Deep Cuts
games use their own darker purple theme: `TWTColor.deepCutsPurple` as the
accent and `TWTBackground(isDeepCuts:)`, mirroring the web's
`[data-deep-cuts-theme]`. Topic colors (`TWTColor.deepCutAccent`, from
`../lib/deepCutColors.ts`) are only for the topic pills. Topic rows are
`id, label` only — there is no emoji or description column.

Room patches: synthesized `Encodable` **omits** nil optionals, so a patch
field set to `nil` is not sent at all. To null a column, write the encode
by hand (see `ClearDeepCutTopicPatch` in `Models/RoomPatch.swift`).

## Visual conventions

- **Backgrounds:** `RootView` draws `TWTBackground` once behind every
  screen (drifting glows, the decade motif, the rolling neon grid floor,
  scanlines). Screens must
  **not** set their own `.background(TWTColor.void)` — it would cover it.
  Modal covers (`HelpModalView`) are the exception.
- **Accent color:** read `@Environment(\.twtAccent) private var accent`
  rather than `TWTColor.marigold`. RootView sets it to the chosen decade's
  color so the TV matches the phones' decade theme. Coral (wrong/urgent)
  and teal (correct) are fixed and never themed.
- **Answer colors:** `TWTColor.options` (A amber, B blue, C violet, D pink)
  mirrors `$option-colors` in `../app/styles/_theme.scss`; the phone uses
  the same colors. Change both together.
- **Type sizes:** pass web-sized values to `TWTFont`; it scales them for
  10-foot viewing (1.4×, 22pt floor). Don't pre-scale.
- **Look:** neon arcade / synthwave. Shared pieces live in
  `Theme/Neon.swift`: `NeonButtonStyle`, `.neonPanel(color)` for cards and
  rows, `.neonGlow(color)` for headings, and `ChromeText` for the few
  marquee titles (intro logo, round countdown, final results) — keep
  chrome rare.
- **Buttons:** every button uses `NeonButtonStyle` — outline + glowing
  label at rest, solid fill when focused, tinted fill when selected.
  `size: .large` for the main action, `TWTColor.neonMagenta` for utility
  buttons, `TWTColor.coral` for destructive ones. Never `.plain`,
  `.tint()`, or the system style: those bring tvOS's white focus halo,
  which tvOS 16 can't switch off. When a button's focus is also driven by
  a `@FocusState` binding, pass `isFocused:` explicitly —
  `@Environment(\.isFocused)` doesn't flip reliably for those.
- **No emoji as icons** in buttons or labels.
- **Motion:** honor `@Environment(\.accessibilityReduceMotion)`. Animate
  offsets/scale/opacity; prefer static `Canvas` drawings and gradients over
  `.blur` or per-frame drawing — the oldest supported hardware is the A8
  Apple TV HD.
- **Per-second updates:** in `QuestionView`, only the countdown and footer
  views re-render each tick (see its doc comment). Keep new effects in
  their own small views rather than reading tick state higher up.

## Player characters

`PlayerAvatarView` draws `PlayerCharacter.forAvatar(player.avatar)` (see
`Services/PlayerCharacter.swift`, a port of `../lib/characters.ts`) from
`Assets.xcassets/Characters/<id>.imageset` on a circle in the player's
color, falling back to the stored emoji. The artwork comes from the Figma
file; keep these SVGs identical to `../public/characters/`.

## tvOS 16 API limits (target is 16, not 17)

- `.onChange(of:)` — single-parameter closure form only.
- Concatenated `Text` segments: `.foregroundColor`, not `.foregroundStyle`.
- No `AccessibilityNotification`; use `UIAccessibility.post`.
- No `ShapeStyle.resolve(in:)`.

## Focus (Siri Remote)

The lobby's focus navigation is fragile. A `.frame(maxWidth: .infinity)` on
`LobbyView`'s players panel once made the decade pills unreachable, and
navigation between the pills and the footer is patched with
`.onMoveCommand`. That handler fires on **every** arrow press while
something inside is focused (not only when the focus engine is stuck), so
only redirect a direction that should always leave the region. That's
why both the decade pills and the Deep Cuts topic pills are single rows:
"down" always means "leave the row". A vertical list broke this (topics
became unreachable or skipped). After any lobby layout change, check with the remote
(arrow keys and Return in the simulator) that focus moves both ways
between the decade pills and the footer.

## Audio

The background music and game sound effects are original 80s synth-pop
audio rendered by `../scripts/compose-audio.mjs` (`node
scripts/compose-audio.mjs` from the repo root writes `.m4a` files to both
`public/sounds/` and `Resources/Sounds/`). Edit the music or sounds there
and re-render; don't hand-replace the files. Picking any decade plays the
one shared `decade-sting` (none for All Decades). Loudness is matched
per file in the script's `LEVELS` table — keep new sounds in line with it.
