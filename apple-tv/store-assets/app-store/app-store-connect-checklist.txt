APP PRIVACY ("Nutrition label")
This form is filled out per App Store Connect app record, so it should
describe what the Apple TV *binary* actually does — not the web app's
footprint. Checked directly against the Swift source: the only
dependency in apple-tv/project.yml is supabase-swift. No Sentry, no
PostHog, no Vercel Analytics, no ad SDK, no location API anywhere in
TimeWarpTrivia/ — those only exist in the Next.js web app, and the
Android TV/Fire TV apps inherit them by loading that website in a
WebView, but this native app never does. (Contrast the Play checklist's
DATA SAFETY FORM section, which is correct for Android TV/Fire TV but
should not be copied here as-is.)

- Contact Info > Name — the chosen nickname. Never entered on the TV
  itself (no nickname field anywhere in the Apple TV app — that only
  happens on a player's own phone/browser); the TV app receives and
  displays it live via Supabase Realtime to run the shared-screen game.
  Declare it anyway, since it's still data this app's functionality
  depends on and displays.
- Contact Info > Email Address — not applicable to this binary. The
  Feedback modal was deliberately cut from the Apple TV app (on-screen
  keyboard text entry is bad UX on a Siri Remote); only the Help modal
  exists. No email is ever collected here.
- User Content > Other User Content — gameplay data (room code,
  questions shown, answers, timing, scores). Required — this is the
  entire point of the app.
- Diagnostics > Crash Data — Not Collected. No Sentry (or any crash
  reporter) is linked into this target.
- Diagnostics > Performance Data, Usage Data > Product Interaction —
  Not Collected. No Vercel Analytics/Speed Insights or PostHog in this
  target.
- Location > Coarse or Precise — Not Collected. No location API of any
  kind, and no geoip-enriching analytics SDK (the PostHog/Vercel geoip
  finding on the Play checklist doesn't apply here — those SDKs aren't
  present).
- Not collected: Health & Fitness, Financial Info, Sensitive Info,
  Contacts, Browsing History, Search History, Purchases — no accounts,
  no payment flow, no address book access anywhere in the app.
- "Data Used to Track You" — No. No advertising, no data sharing with
  data brokers or ad networks, no IDFA use, no analytics SDK at all on
  this binary.
- Linked to your identity vs. not linked: the nickname/gameplay data
  above is not linked to a persistent identity — there's no account,
  and a nickname only exists for the lifetime of one ephemeral room.
  Default to "Not Linked."

AGE RATING QUESTIONNAIRE
- No violence, no gambling, no in-app purchases, no unrestricted web
  access (the app never opens arbitrary URLs, only /tv on
  timewarptrivia.com). Expect 4+.
- User Generated Content: the free-text nickname field is the one
  UGC-adjacent surface (JoinScreen.tsx-equivalent web flow) — answer the
  questionnaire's UGC question honestly. Apple's Guideline 1.2 (Safety —
  User-Generated Content) specifically wants a way to filter objectionable
  content and remove abusive users for any UGC surface; both already
  exist and are worth citing if App Review asks: lib/nicknameFilter.ts
  blocks a slur/profanity list client- and server-side (so it can't be
  bypassed via devtools), nicknames are capped at 20 characters and only
  ever visible inside that one ephemeral room (never public/global), and
  the host can remove any player in two presses. There's no separate
  player-to-player reporting flow — the host-removal path is the
  moderation mechanism in place, same gap the Play checklist flagged for
  Android.
